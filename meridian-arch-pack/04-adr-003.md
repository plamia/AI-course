# ADR-003: Centralized Identity Management and Customer Federation via Auth0

## Status
Accepted

## Owner
Security & Architecture Teams

## Source and Freshness
- **Source:** Meridian Case A brief; GDPR compliance requirements; multi-region loyalty fragmentation.
- **Last Reviewed:** 2026-09-26
- **Status:** Accepted

## Review Trigger
Re-evaluate if enterprise identity provider migration occurs, sovereign data residency mandates force regional IDAM segregation, or scaling thresholds are exceeded.

## Context
Customers currently maintain 3–4 fragmented loyalty accounts across 22 regional commerce stacks. We need a unified identity provider that supports GDPR-compliant customer federation, secure single sign-on (SSO), and seamless omnichannel authentication without creating a new internal monolith.

## Decision
We will use **Auth0** as the centralized Identity and Access Management (IDAM) provider for all customer and associate authentication across all regional storefronts and mobile apps.

## Alternatives Considered
1. **Maintain Regional IDAM Repositories:** Rejected because decentralized regional user stores perpetuate customer account fragmentation and make the unified loyalty program impossible to deliver.
2. **Build Custom OAuth2/OIDC Service in-house:** Rejected because building custom identity services diverts engineering effort away from core commerce unification and introduces unnecessary security vulnerabilities and compliance overhead.

## Consequences
- **Positive:** Centralized user session management; robust multi-factor authentication (MFA); compliance with GDPR data handling standards.
- **Negative:** External SaaS dependency for core identity services and associated subscription costs.

## Agent-Readable Summary
All customer and associate authentication MUST integrate with Auth0 via OIDC tokens validated at the Apollo API Gateway. Do not implement custom password stores, direct database credential checks, or decentralized regional identity databases. Entity resolution for merged profiles must be handled in designated identity-resolution services, not directly within Auth0 raw token stores.
